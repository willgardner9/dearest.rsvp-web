# Auth and Tenants (Web) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the login, signup, verification, password reset, onboarding, tenant, members, and invite pages to the web app.

**Architecture:** TanStack Router with code-based routes. The router context holds the TanStack Query client. Route `beforeLoad` functions read the `GET /auth/me` query and redirect. Pure functions hold the redirect rules, so that unit tests cover them without a browser. The session is an `HttpOnly` cookie, so the web app never touches a token. Every call uses `credentials: "include"`.

**Tech Stack:** React 19, Mantine 9 (`@mantine/core`, `@mantine/form`), TanStack Query 5, TanStack Router 1 (`@tanstack/react-router`), Vite+ (`vp`), Vitest through `vite-plus/test`.

**Spec:** `../dearest.rsvp-api/docs/superpowers/specs/2026-11-14-auth-design.md` (in the API repository).

**Depends on:** the API plan `dearest.rsvp-api/docs/superpowers/plans/2026-11-14-auth-api.md`. Its error codes and response shapes are the contract. For the manual checks, run the API from its `auth` branch with `docker compose up --build`.

## Global Constraints

- Paths are exactly: `/login`, `/signup`, `/verify-email`, `/verify-email/confirm`, `/forgot-password`, `/reset-password`, `/invite/$token`, `/onboarding`, `/new-wedding`, `/w/$tenantId`, `/w/$tenantId/members`.
- No link, menu, or button in the app points to `/new-wedding`.
- Show the tenant switcher only when `memberships.length >= 2`. With fewer, show no tenant list or any other sign that other tenants exist.
- `localStorage` key for the last opened tenant: `dearest.lastTenantId`. Wrap every read and write in `try/catch`.
- User-facing copy uses "wedding", not "tenant".
- Use only the `error` codes from the API plan. Show a message from `errorMessage(code)` (Task 1), never the raw code.
- Run `yarn fmt` before each commit. The pre-commit hook checks the format.

## Review Focus

1. **Open redirect through `?redirect=`.** `/login?redirect=//evil.example` or `https://evil.example` must go to `/` after login. Test: Task 2 `safeRedirect_rejects_external_targets`.
2. **A stale last-tenant ID.** `localStorage` holds the ID of a wedding that the user is no longer a member of, or a value that is not an ID. `/` must go to the first membership, not to a 404 page. Test: Task 2 `resolveHome_ignores_unknown_last_tenant`.
3. **The verification link opened in a browser with no session** (for example on a phone). The confirm page must say that the email is verified and offer login, not show an error. Test: Task 2 `afterVerifyTarget_without_session_goes_to_login`.
4. **The verification link opened two times.** The second call gets `invalid_token`. If `/auth/me` then says the user is verified, the page must treat it as success. Test: Task 2 `afterVerifyTarget_treats_invalid_token_as_success_when_verified`.
5. **The unverified screen after the user verifies in another tab.** Returning to the tab must move the user on without a manual reload. Test: Task 3 manual check, step "verify in a second tab".

**Interfaces:**

- Produces:
  - `apiFetch<T>(path: string, init?: RequestInit & { json?: unknown }): Promise<T>`. It always sends `credentials: "include"`. When `json` is set, it sends `JSON.stringify(json)` as the body with `Content-Type: application/json`, and the method defaults to `POST`.
  - `types.ts`:
    - `Membership { tenant_id: string; tenant_name: string }`
    - `Me { user: { id: string; email: string; name: string; email_verified: boolean }; memberships: Membership[] }`

    - `Member { user_id: string; name: string; email: string }`
    - `Invite { id: string; email: string; invited_by_name: string; expires_at: string }`
    - `InvitePreview { tenant_name: string; inviter_name: string; email: string; account_exists: boolean }`
  - `errors.ts`:
    - `errorCode(error: unknown): string | null`: `body.error` of an `ApiError`, else null.
    - `errorMessage(error: unknown): string`: the copy below, or `"Something went wrong. Try again."`.

| Code                    | Message                                                      |
| ----------------------- | ------------------------------------------------------------ |
| `invalid_credentials`   | `The email or password is not correct.`                      |
| `email_taken`           | `An account with this email already exists. Log in instead.` |
| `invalid_input`         | `Check the fields and try again.`                            |
| `invalid_token`         | `This link is not valid or has expired.`                     |
| `already_member`        | `This person is already a member of the wedding.`            |
| `invite_email_mismatch` | `This invite is for a different email address.`              |
| `rate_limited`          | `Too many attempts. Wait a few minutes and try again.`       |
| `not_found`             | `We could not find that.`                                    |

- `auth.ts`:
  - `meKeys.all = ["me"]`
  - `fetchMe(): Promise<Me | null>`: returns null on `ApiError` status 401.
  - `meQueryOptions`: `queryOptions({ queryKey: meKeys.all, queryFn: fetchMe, staleTime: 30_000 })`
  - `useMe()`
  - Mutations, each calls `queryClient.setQueryData(meKeys.all, ...)` or `invalidateQueries({ queryKey: meKeys.all })` on success: `useSignup()` (`{email, password, name}` → `Me`), `useLogin()` (`{email, password}` → `Me`), `useLogout()` (sets me to `null`, then `queryClient.clear()` except me), `useVerifyEmail()` (`{token}`), `useResendVerification()`, `useRequestPasswordReset()` (`{email}`), `useConfirmPasswordReset()` (`{token, password}`, sets me to `null`).
- `tenants.ts`: `tenantKeys`, `useTenant(tenantId)`, `useMembers(tenantId)`, `useCreateTenant()` (`{name}` → `Tenant`, invalidates me).
- `invites.ts`: `inviteKeys`, `useInvites(tenantId)`, `useCreateInvite(tenantId)` (`{email}`, invalidates the list), `useCancelInvite(tenantId)` (`inviteId`), `useInvitePreview(token)` (`retry: false`), `useAcceptInvite(token)` (`{name?, password?}` → `{tenant_id}`, invalidates me).
- Keep `health.ts` and `HealthCheck.tsx`. Nothing renders `HealthCheck` after Task 2.

### Task 2: Router, redirect rules, and route guards

**Files:**

- Create: `src/routing.ts`, `src/routing.test.ts`, `src/router.tsx`, `src/components/AuthCard.tsx`
- Modify: `src/App.tsx`, `package.json`

**Interfaces:**

- Consumes: `Me`, `meQueryOptions` (Task 1).
- Produces in `routing.ts`:
  - `resolveHome(me: Me | null, lastTenantId: string | null): string`:
    - `null` → `/login`
    - not verified → `/verify-email`
    - 0 memberships → `/onboarding`
    - else `/w/<id>`, where `id` is `lastTenantId` if it is one of the memberships, else `memberships[0].tenant_id`.
  - `safeRedirect(target: string | undefined): string`: returns `target` only if it starts with `/` and not with `//` or `/\`. Else `/`.
  - `afterVerifyTarget(result: "ok" | "invalid_token", me: Me | null): { status: "verified" | "invalid"; next: string }`:
    - `"ok"` with `me` → `{verified, "/"}`; `"ok"` without `me` → `{verified, "/login"}`
    - `"invalid_token"` with `me?.user.email_verified` → `{verified, "/"}`; else `{invalid, me ? "/verify-email" : "/login"}`
  - `showSwitcher(me: Me | null): boolean`: `(me?.memberships.length ?? 0) >= 2`.
  - `readLastTenant(): string | null` and `writeLastTenant(id: string): void` (key `dearest.lastTenantId`, `try/catch`).
- Produces in `router.tsx`:
  - `interface RouterContext { queryClient: QueryClient }`
  - `router = createRouter({ routeTree, context: { queryClient } })` and the `Register` type declaration.
  - Guard helpers used by `beforeLoad` (each one calls `context.queryClient.ensureQueryData(meQueryOptions)` and may `throw redirect(...)`):
    - `requireLoggedOut`: a logged-in user goes to `resolveHome(me, readLastTenant())`.
    - `requireUnverified`: `null` → `/login`. Verified → `/`.
    - `requireVerified`: `null` → `/login?redirect=<current path>`. Unverified → `/verify-email`. Returns `{ me }`.
    - `requireNoTenants`: as `requireVerified`, then a user with memberships goes to `/`.
    - `requireMember`: as `requireVerified`, then if `params.tenantId` is not in the memberships, go to `/`. Calls `writeLastTenant(params.tenantId)`.
  - Route `/` has only a `beforeLoad` that redirects to `resolveHome(me, readLastTenant())`.
  - A not-found route renders a short "Page not found" with a link to `/`.
  - In this task, each page route renders a placeholder `<Title>` with the page name. Tasks 3 to 7 replace them.
